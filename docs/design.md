# Phone controlled immersive video

2026-11-05. User authorized implementation, GitHub push and live Pages publication.

Updated 2026-11-06: the root URL is a shared session launcher with an immediate QR. Its fragment-only invitation opens the viewer on Quest/immersive-capable browsers and compact controls on smartphones; uncertain devices choose a role, and explicit viewer/controller links always override detection. The root downloads no video and constructs no remote connection. The viewer keeps the supplied invitation across recoverable connection failures, rather than generating a different room. End/expiry clear keys and role links locally. A copied bearer can open a separate viewer; a fresh viewing pair should generate a new QR.

The visible interface is limited to Immersive Video Player, a QR and functional controls/status. No marketing, setup prose or Quest Browser instructions. Viewer Connection, Playback and View use native exclusive details groups. The phone is a full-window native video player with Start/Pause/Stop and an SVG headset button opening a connection dialog. The dialog closes on authenticated ready. Phone uses the bundled asset directly, with no WebGL renderer or peer video track. Header/footer anchor a stretch body; width and height drive spacing/control/type tokens. Pinned Pretext measures actual labels; unfittable enlarged text uses readable document flow. Dialogs have their own scroll policy.

The viewer and phone select Enable then Connect. The user selects VR with a headset gesture; only video appears in the immersive session. The viewer remains authoritative; one invited phone requests transport scope and exposes Start/Pause/Stop. Stop pauses and resets the common timeline to zero, separately from Disconnect. Viewer settings remain local. Phone departure frees the viewer for another invited phone.

Reuse the BRSP/1 core and pinned VDO.Ninja 1.5.5 adapter. Only data crosses WebRTC: both devices fetch the same bundled MP4 over HTTPS. Bounded clock samples and a 500 ms future play anchor coordinate the players. Green pulse requires authenticated ready, a real returned viewer state younger than two seconds, clock sampling, ready/non-seeking local video, matching playing/paused state and position within 350 ms of the authoritative anchor. Other states are red with a matching accessible name. Reduced motion disables the pulse. This is state/preview agreement, not proof of hardware frame lock. Command errors remain visible on the phone player; a rejected viewer play publishes a paused timeline.

Projection defaults to Kodak circular fisheye for the square Jona source, with adjustable lens angle, yaw/pitch, view FOV, equirectangular 180/360 and flat alternatives. A sphere shader maps viewing rays to the circular source independently for each eye (the source is mono).

Static Vite build with relative paths, Three.js WebXR, QR generation and actual Pretext measurement. No backend, camera/microphone capture, tracking, arbitrary remote URLs, native bridge or service worker. Bounded commands, 250 ms state heartbeat, 2 second stale threshold, 30 minute session expiry, acknowledgements and one active controller. Internet is required for VDO signaling/ICE; same Wi-Fi is optional.

Publish only this curated browser repository and the specifically authorized full-length Jona web encode. Retain library licenses and hashes. Older native work stays in the original workspace.
